# ADR-014: Память и Приватность (Мультипользовательскость)

**Статус:** accepted
**Дата:** 23.11.2026
**Связанные доки:** ARCHITECTURE.md §4.3, §7.1; GLOSSARY.md; ADR-015

## Контекст

Для работы с несколькими пользователями (Telegram, VK, веб) нужна архитектура памяти, которая, с одной стороны, позволяет Грише накапливать общие знания о мире, а с другой — гарантирует конфиденциальность личных данных и сохраняет память о пользователе навсегда (без TTL).

## Решение

Память Гриши разделена на два слоя.

### 1. Общий граф (Global Knowledge Graph)
- **Что хранится:** объективные знания о мире (`трава`, `солнце`, `Python`, `как программировать`).
- **Доступ:** читают все пользователи.
- **Изменения:** Гриша может дополнять этот граф из открытых источников (книги, веб).
- **Безопасность:** сюда никогда не попадают личные факты пользователей.

### 2. Личные подграфы (User Subgraphs)
- **Что хранится:** факты, события и предпочтения конкретного пользователя (`Саша любит кофе`, `Саша вчера ходил в кино`).
- **Структура:** подграф привязан к узлу `[Пользователь_Саша]`.
- **Срок жизни:** **Бессрочно.** TTL нет. Если пользователь вернется через год, Гриша будет помнить его историю.
- **Изоляция:** при общении с Сашей Гриша видит только `Общий граф` + `Подграф_Саши`. Гриша не может прочитать подграф Маши, так как каждый запрос к БД жестко фильтруется по owner_id. (В v0.1 это программная изоляция; физическое разделение на разные процессы — задача v0.2).

### 3. Рабочая память (Working Memory)
- Текущий контекст диалога (активные узлы).
- Очищается по TTL или при завершении сессии.

### 4. Прозрачность (Open Source)
- Поскольку проект open-source, данные хранятся локально у создателя/пользователя (PostgreSQL).
- Диалоги (сырой текст) не хранятся вечно — только извлеченные знания (узлы и рёбра) с метаданными (источник = пользователь X).

## Последствия
- **Плюс:** Гриша помнит всех, но не сливает секреты. Узел `[Пользователь]` становится центром личного мира.
- **Минус:** запросы к базе данных должны всегда фильтроваться по `owner_id` (проверка прав доступа на уровне запросов к PostgreSQL).
