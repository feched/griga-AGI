# ADR-001: Онтология графа

**Статус:** accepted
**Дата:** 22.11.2026
**Связанные доки:** ARCHITECTURE.md §2, §5; GLOSSARY.md

## Контекст

Нужно определить, какие сущности есть в графе знаний и как они связаны.
От этого зависит: парсинг текста (ADR-002), валидация (ADR-008), реификация,
производительность на домашнем железе.

Рассматривались варианты:
1. Один тип ребра (`связано_с`) — просто, но теряется смысл.
2. Фиксированный список типов — контроль, но не гибко.
3. Всегда реифицировать — выразительно, но граф взрывается.
4. Гибрид: базовые типы фиксированы + реификация нестандартных отношений.

## Решение

**Вариант 4 (гибрид) с ленивой реификацией.**

### 4 базовых типа рёбер (фиксированы, не реифицируются)

| Тип | Смысл | Пример |
|---|---|---|
| `это` (is-a) | Наследование | `трава — это — растение` |
| `часть` (part-of) | Композиция | `стебель — часть — трава` |
| `свойство` (has-property) | Атрибут | `трава — свойство — зелёная` |
| `связано_с` (related-to) | Общая ассоциация, «мусорка» | `трава — связано_с — футбол` |

Обоснование: `это`, `часть`, `свойство` — структурные отношения, на них
работает логический вывод (наследование, транзитивность). Их надо
контролировать. `связано_с` — «мусорка», чтобы не блокировать обучение.

### Реификация нестандартных отношений — ленивая, три уровня зрелости

| Уровень | Физически | Когда |
|---|---|---|
| 0. Ребро с меткой | `[A] ──(метка)──> [B]`, метка в свойствах ребра | Первое упоминание |
| 1. Лёгкий узел | `[A] ──> [отношение] ──> [B]`, у узла имя и связи | Встретилось N раз (N=3, TBD) или понадобилось в выводе |
| 2. Полный узел | То же + метаданные, свои связи, участие в активации | Важное отношение, привязка фактов |

**Для кода все три уровня выглядят одинаково:** `get_node("растёт_на")`
всегда возвращает узел. На уровне 0 он «виртуальный» — собирается
из ребра на лету.

### Канонизация на входе (обязательна)

Перед созданием отношения — нормализация:
- синонимы: «произрастает», «растет», «растёт на» → `растёт_на`;
- ё/е, регистр, пунктуация — приводятся к канону.

Список синонимов — TBD (ADR-002).

### Механизмы контроля

- **Канонизация** (см. выше) — против дубликатов.
- **Архивация** — узел-отношение, встретившийся 1 раз и неиспользуемый
  N дней, уходит в архив (не удаляется, не участвует в активации).
- **Лимит роста** — максимум новых узлов за один такт обучения (100, TBD).

## Альтернативы

- **Вариант 3 (всегда реифицировать):** отклонён — граф взрывается
  на больших текстах, производительность падает.
- **Вариант 2 (фиксированный список):** отклонён — не хватает гибкости
  для новых отношений.
- **Вариант 1 (один тип):** отклонён — теряется смысл связей,
  логический вывод невозможен.

## Последствия

**Плюс:**
- Выразительность реификации, когда нужно.
- Компактность на старте (редкие отношения — рёбра).
- Граф растёт постепенно, «как живая ткань».
- Обратная совместимость: если завтра решим все отношения сделать
  узлами — понижаем порог, ничего не ломается.

**Минус / цена:**
- Сложнее реализация (три уровня, виртуальные узлы).
- Нужна канонизация с первого дня (иначе дубликаты).
- Нужна архивация (иначе граф пухнет).
- Производительность: обход по рёбрам (уровень 0) быстрее, чем по узлам.

**Что разблокирует:**
- ADR-002 (парсинг) — понятно, что извлекать.
- ADR-008 (валидация) — понятно, что считать противоречием.
- §2, §5, §6 ARCHITECTURE.

## MVP vs масштабирование

**MVP (v0.1): уровень 0.** Все нестандартные отношения — рёбра с канонической
меткой. Метаданные (источник, уверенность, доверие) хранятся на ребре.
API графа не различает ребро и узел-отношение снаружи: `get_relation(A, B)`
работает одинаково на всех уровнях.

**Масштабирование (v0.2+): ленивая реификация (уровни 1–2).** Когда отношение
встретилось N раз и «созрело», оно мигрирует в узел. Миграция — трансформация
данных (пробег по рёбрам с меткой → создание узла → замена), не переписывание.
Версионирование позволяет откатить.

**Условия обратимости (обязательны с v0.1):**
- метка отношения на ребре — с первого дня;
- метаданные — на ребре, не в отдельной таблице;
- API графа — единый для всех уровней;
- версионирование графа — с v0.1.
