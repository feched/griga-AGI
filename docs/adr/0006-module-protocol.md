# ADR-006: Протокол взаимодействия модулей

**Статус:** accepted
**Дата:** 23.11.2026
**Связанные доки:** ARCHITECTURE.md §4

## Контекст
Нужен четкий контракт того, как данные передаются между слоями при обработке одной реплики пользователя.

## Решение
В v0.1 используется жесткий синхронный конвейер. Каждый шаг — это функция, которая принимает объект и возвращает объект.

1. **Input:** `Kernel` получает от пользователя строку `text` и `user_id`.
2. **Perception (Парсер):** `Parser.parse(text)` возвращает три потока (см. ADR-002):
   - `nodes` (список концептов для активации).
   - `statements` (факты для записи в граф с учетом polarity).
   - `markers` (тип реплики: вопрос/эмоция).
3. **Memory (Запись):** Если есть `statements`, они пишутся в `PostgreSQL` (с привязкой `owner_id`).
4. **Thinking (Активация):** `Spreader.activate(nodes)` берет `nodes` из шага 2 и запускает волну (см. ADR-003). Возвращает список `active_nodes` (Топ-5).
5. **Speech (Генерация):** `Generator.generate(active_nodes, markers)` берет активные узлы и маркеры, ищет подходящую конструкцию (см. ADR-004) и возвращает готовую строку `response`.
6. **Output:** `Kernel` отправляет `response` обратно в CLI.

## Последствия
- Любой модуль можно тестировать отдельно (например, подать в Spreader готовый список узлов и посмотреть, что загорится).
