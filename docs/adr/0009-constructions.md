# ADR-009: Банк конструкций (Генерация v0.1)

**Статус:** accepted
**Дата:** 23.11.2026
**Связанные доки:** ADR-004; ADR-008; ARCHITECTURE.md §6.2

## Контекст

Как именно из активных узлов рождается текст? Нужен стартовый набор правил,
чтобы Гриша мог связно ответить, не обращаясь к LLM. Ответ должен быть
заземлён: каждое содержание берётся из графа, а не придумывается.

## Решение

Конструкции хранятся отдельно от кода — в
[`griga/speech/constructions.json`](../../griga/speech/constructions.json).
Это данные: банк можно расширять без изменения генератора. Загрузчик
[`griga/speech/constructions.py`](../../griga/speech/constructions.py)
валидирует файл на старте и падает с понятной ошибкой, если схема нарушена.

### Схема конструкции

```json
{
  "id": "answer_is_a",
  "intent": "ответить_прямо",
  "template": "{X} — это {Y}.",
  "graph_pattern": {"relation": "is_a", "direction": "forward"},
  "slots": {
    "X": {"pos": "noun", "case": "nominative"},
    "Y": {"pos": "noun", "case": "nominative"}
  },
  "weight": 1.0,
  "emotion": null,
  "yes_no": false
}
```

Поля:

- **`id`** — уникальный строковый идентификатор; дубликаты запрещены.
- **`intent`** — одно из значений `Intent` (см. `griga/speech/intents.py`);
  неизвестное намерение — ошибка загрузки.
- **`template`** — текст с плейсхолдерами `{X}`, `{Y}` и служебными
  `{VERB_PRES}`, `{PREP}`, `{EMOTION_ADV}`, которые заполняет генератор.
- **`graph_pattern`** — `relation` (тип ребра из `RelationType` или `null`)
  и `direction` (`forward` / `reverse`). Паттерн задаёт, какое ребро
  рабочей памяти может заполнить слоты.
- **`slots`** — описание слотов: `pos` (`noun` / `adjective`), `case`
  (один из падежей pymorphy2 или `auto`), необязательный `agree_with`.
- **`weight`** — приоритет выбора среди подходящих конструкций (больше —
  выше). Это не вероятность, а порядок сортировки.
- **`emotion`** — необязательная привязка к эмоции реплики
  (`радость`, `грусть`, ...).
- **`yes_no`** — конструкция предназначена для вопроса «да/нет».

### Правила валидации

Загрузчик проверяет:

1. файл содержит непустой список `constructions`;
2. `id` непустой и не повторяется;
3. `intent` входит в `Intent`;
4. `template` непустой;
5. `relation` входит в `RelationType` (или отсутствует);
6. `direction` — `forward` или `reverse`;
7. `pos`/`case` слотов входят в допустимые множества;
8. каждый плейсхолдер шаблона имеет слот (кроме служебных);
9. каждый слот используется в шаблоне.

### Выбор и мониторинг (ADR-004)

1. `choose_intent` определяет намерение по маркерам и рабочей памяти.
2. Генератор берёт конструкции этого намерения, отбрасывает несовпавшие
   по эмоции и незаполнимые слоты.
3. Кандидаты сортируются по весу (совпадение эмоции — выше).
4. Каждый отрендеренный ответ проходит мониторинг; при провале берётся
   следующий кандидат, но не более `generation.max_attempts = 3`.
5. Если все попытки провалились — честный fallback «Пока не могу ответить…».

### Стартовый банк

В v0.1 — **42 конструкции**:

| Намерение | Кол-во |
|---|---|
| `ответить_прямо` | 16 |
| `запомнить_факт` | 7 |
| `ответить_с_оговоркой` | 5 |
| `признать_незнание` | 5 |
| `выразить_эмпатию` | 4 |
| `поздороваться` | 2 |
| `уточнить` | 2 |
| `отказать` | 1 |

По граф-паттернам: `related_to` — 11, `is_a` — 6, `part_of` — 5,
`has_property` — 4, без паттерна — 16 (реплики без фактов).

Склонение слотов выполняет pymorphy2: существительные ставятся в нужный
падеж, прилагательные согласуются с опорным словом, глаголы спрягаются.

## Последствия

- Банк растёт как данные; генератор не меняется.
- Валидация на старте не даёт «тихо» сломать генерацию опечаткой в JSON.
- Новые намерения добавляются сначала в `Intent`, затем конструкциями.
- Ответы остаются заземлёнными: слоты заполняются только узлами и рёбрами
  активного подграфа.
